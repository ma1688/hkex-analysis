## 📖 优化背景

### 问题现状
V2.1版本虽然新增了分类字段，但存在以下问题：

1. **字段冗余**: 多个字段可通过计算获得（如 `section_count`, `total_chars`）
2. **分类重叠**: `document_type` 与 `document_category` 存在部分语义重叠
3. **技术字段污染**: 处理状态等技术字段混入业务表
4. **存储浪费**: 大量低频字段占用存储空间

### 优化目标
1. 删除冗余和低频字段
2. 保留核心业务字段
3. 优化分类系统
4. 提升查询和写入性能

## 🔍 字段分析与决策

### documents_v2 表优化详情

#### ❌ 删除字段（9个）

| 字段名 | 删除原因 | 替代方案 |
|--------|----------|----------|
| `title` | 与 `announcement_title` 和 `file_path` 重复 | 使用 `announcement_title` |
| `document_type` | 与 `document_category` 语义重叠 | 使用两级分类系统 |
| `document_subtype` | 使用频率低 | 移至 `metadata` JSON |
| `processing_date` | 可用 `created_at` 替代 | 使用 `created_at` |
| `file_size` | 非核心业务字段 | 需要时从文件系统获取 |
| `processing_status` | 技术元数据 | 移至 `metadata` 或日志 |
| `error_message` | 应在日志中记录 | 使用独立日志系统 |
| `section_count` | 可从 `document_sections` 表COUNT得出 | `SELECT COUNT(*) ...` |
| `total_chars` | 可从 `document_sections` 表SUM得出 | `SELECT SUM(LENGTH(content)) ...` |
| `updated_at` | 文档很少更新 | 保留 `created_at` 足够 |

### 分类系统优化

#### V2.1 三级分类（已废弃）
```
document_category (一级目录)
  ↓
announcement_category (二级目录)
  ↓
document_type (业务类型: rights/placing/ipo/consolidation)
```

**问题**: `document_type` 与目录分类存在语义重叠

#### V2.2 两级分类（当前方案）
```
document_category (一级目录)
  ↓
announcement_category (二级目录)
```

**优势**:
1. 分类层次清晰，无语义冲突
2. 直接映射目录结构
3. 业务类型可从目录分类推断
